## Findings

### F-2-3 / F-3-1 — BLOCKING — Back loses the reader’s scroll position after a normal click

**Quote/location:** This reopens review-2 finding `F-2-3`. On the live 390 px page, I opened `/#how`, scrolled to `window.scrollY = 1232`, used Playwright’s normal click on header “Privacy,” then used Back. The restored page focused the h1 but remained at `scrollY = 11` after four seconds. `site/src/main.ts` only calls `heading?.focus({ preventScroll: true })`; it does not record and restore a scroll position.

**Why this fails:** A visitor checking Privacy from the workflow loses their place. This is a stated routing requirement and is an earlier finding that is not fixed in the real click path. The existing browser test uses `element.click()` in page JavaScript, which did not reproduce the physical-click behavior.

**Concrete fix:** Save the current scroll position before same-origin navigation, keyed to the current history entry; after Back/Forward, restore it after the new h1 receives focus. Change the browser test to activate the visible link with `locator.click()` and assert the restored value, rather than invoking DOM `click()` directly.

### F-3-2 — MEDIUM — The demo replay button also invokes the install-command clipboard handler

**Quote/location:** On live `/demo/`, activating “Run sample check” first changes its label to “Clipboard access failed. Select the command above.” At 1.6 seconds it becomes “Replay sample check”; at 2.6 seconds it becomes “Copy install command.” The completed result still says “The handoff does not match.” In `site/src/main.ts`, the global `document.querySelector<HTMLButtonElement>(".copy-button")` listener attaches to the first `.copy-button`, which is `#play-demo`; the demo handler is separately attached to that same button.

**Why this fails:** The demo’s sole replay action communicates an unrelated clipboard error and finally names an install action it cannot perform. This is confusing in the central try-it path and violates the plain-language action rule.

**Concrete fix:** Attach the clipboard listener only to the install button (for example, give it `id="copy-install-command"`), or remove `copy-button` from `#play-demo`. Add a browser test that clicks “Run sample check,” asserts the three-path result, and asserts that the control ends as “Replay sample check” without clipboard copy text.
